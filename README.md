# Только вдвоём? — интерактивная концертная открытка

Небольшой production-like прототип на React + Vite: интро как мини-фильм, живая ночная атмосфера Санкт‑Петербурга, музыкальные карточки и памятный digital demo-билет.

## Запуск одним нажатием (Windows)

Дважды нажмите [`Запустить открытку.cmd`](./%D0%97%D0%B0%D0%BF%D1%83%D1%81%D1%82%D0%B8%D1%82%D1%8C%20%D0%BE%D1%82%D0%BA%D1%80%D1%8B%D1%82%D0%BA%D1%83.cmd). Скрипт проверит Node.js, при первом запуске установит зависимости, запустит Vite на всех сетевых интерфейсах (`0.0.0.0:5173`), откроет открытку в браузере и напечатает адрес компьютера в локальной сети.

Окно скрипта нужно оставить открытым, пока сайт используется. Телефон или другой компьютер можно подключить по адресу `http://<LAN-IP>:5173`, если они находятся в той же Wi‑Fi/локальной сети и Windows Firewall разрешает входящие подключения.

Требования: Node.js LTS и доступ к интернету при первом запуске. Ручной запуск:

```bash
pnpm install
pnpm run dev
```

Production-сборка проверяется командой `pnpm run build`.

## Локальная сеть и публичный сайт

LAN-адрес из launcher работает только внутри текущей сети и пока окно Vite запущено. Это не публичная ссылка и не backend.

Чтобы открыть открытку людям через интернет, разместите production-сборку `dist/` на статическом хостинге с HTTPS и SPA fallback: запросы к неизвестным путям должны возвращать `index.html`. Локальный `localhost` и адрес `192.168.x.x` снаружи недоступны. Сервер приложения, база данных и фиктивные API-endpoint'ы не нужны.

### Публикация на `wuiofgajsfs.cfd`

Проект уже подготовлен к публикации на Netlify: [`netlify.toml`](./netlify.toml)
собирает сайт командой `npm run build`, публикует папку `dist/` и сохраняет
работу ссылок вида `/ticket/...` после обновления страницы.

Чтобы открыть сайт по своему домену, один раз нужны входы в аккаунты хостинга и
управления доменом — без них приложение не может безопасно менять DNS за вас.

1. Создайте бесплатный сайт на [Netlify](https://app.netlify.com/drop) и перетащите
   в окно папку `dist` после выполнения `pnpm run build`. Сервис выдаст временный
   адрес `*.netlify.app`.
2. В Netlify откройте **Domain management → Add a domain alias**, добавьте
   `wuiofgajsfs.cfd` и дождитесь подсказки о DNS.
3. В панели DNS домена замените текущую A-запись корня домена на `75.2.60.5`
   (или используйте ALIAS/ANAME на `apex-loadbalancer.netlify.com`, если такая
   запись доступна). Добавьте `www` как CNAME на выданный Netlify адрес
   `имя-сайта.netlify.app`.
4. Дождитесь выпуска HTTPS-сертификата и проверьте
   `https://wuiofgajsfs.cfd/ticket/…` — ссылка должна открываться и после
   обновления страницы.

Сейчас DNS корня `wuiofgajsfs.cfd` указывает на другой IP-адрес и HTTPS-сайт
там не отвечает; никаких DNS-записей или внешних аккаунтов проект не меняет.
Потребуется заменить старую A-запись, а не добавить вторую: несколько A-записей
для корня могут мешать выпуску HTTPS.

## Сценарий и интерфейс

- Интро разворачивается по шагам: чёрный экран → текущие дата и время устройства → `САНКТ‑ПЕТЕРБУРГ` → ночной городской слой → «У меня есть один вопрос…». Музыка и процедурный ambient не стартуют до первого действия пользователя.
- Дата и время в заставке форматируются на клиенте из часов устройства и обновляются раз в минуту; это не дата концерта.
- После первого взаимодействия включаются процедурный Web Audio ambient, частицы, дымчатые слои, световые полосы и мягкий grain/parallax. Движение частиц реагирует на указатель; `prefers-reduced-motion` уменьшает эффекты и звук.
- Theme Engine меняет палитру под выбранного артиста. Карточки на сенсорных экранах образуют горизонтальную touch/swipe-карусель, на больших экранах остаются в просторной сетке.
- На фоне используется локальная фотография Исаакиевского собора, Невы и Благовещенского моста: [`public/assets/spb-isaac-neva.jpg`](./public/assets/spb-isaac-neva.jpg). Оригинал: [Wikimedia Commons — Blagoveshchensky Bridge (winter and ice) and Saint Isaac's Cathedral](https://commons.wikimedia.org/wiki/File:Blagoveshchensky_Bridge_(winter_and_ice)_and_Saint_Isaac%27s_Cathedral.jpg).
- После выбора карточки идёт cinematic-переход к площадке: город, артист, адрес и venue marker. Затем показываются данные события, площадки и кнопка подтверждения.

## Выбор концерта и честные данные

В текущем flow нет выбора зон, секторов, рядов, мест или схемы зала. После venue-экрана пользователь подтверждает выбранную историю, и открытка сразу запускает короткую анимацию печати билета.

Даты, площадки и ссылки на источники хранятся в [`src/data/concerts.js`](./src/data/concerts.js). Наличие билетов и цены могут измениться; приложение не выдаёт их за гарантию покупки и не резервирует места.

Для пользовательского варианта название концерта обязательно, а дата, время, площадка и ссылка на афишу — необязательные поля. Ссылка принимается только в формате `http://` или `https://`; она используется как внешний poster/source URL и не загружается на сервер. Если поле пустое, остаётся честная подпись «по договорённости» и локальная abstract-афиша.

## Музыка

Звук выключен по умолчанию. После включения глобального `SOUND ON` hover/focus/tap запускает короткий легальный Apple Music/iTunes preview; при смене карточки предыдущий канал плавно затихает, а `activeAudioArtist` хранит активный preview. Процедурный ambient включается только после пользовательского жеста. Полные коммерческие записи в проект не скачиваются.

Для GONE.Fludd используется именно `BOYS DON'T CRY`; официальный трек и preview находятся в [`src/data/concerts.js`](./src/data/concerts.js).

## Digital demo-билет

После подтверждения площадки создаётся уникальный `Ticket ID`, проигрывается staged-анимация «билет напечатан», затем открывается памятный digital demo-билет с артистом, датой, временем, площадкой, городом и QR-кодом.

- QR кодирует Ticket ID и данные выбранной истории в demo-формате; это не пропуск на мероприятие и не платёжный документ.
- На финальном экране оставлены только два действия: **«Поделиться в Telegram»** и **«Сохранить билет»**.
- Telegram открывает подготовленное сообщение с данными концерта и ссылкой, если она доступна; отправка подтверждается пользователем в самом Telegram.
- «Сохранить билет» создаёт PNG локально в браузере через canvas; данные и изображение не отправляются на backend.
- Персональные данные не собираются и не помещаются в URL. Ticket ID — демонстрационный идентификатор.

## Структура

- `src/App.jsx` — состояние сценария, локальные дата/время, Theme Engine, ambient/audio, touch-friendly карточки, custom event, печать, QR, Telegram и PNG.
- `src/data/concerts.js` — факты о мероприятиях, preview и ссылки на источники.
- `src/styles.css` — design tokens, адаптивные темы, responsive/mobile, swipe layout, cinematic-слои, ticket/print animation и reduced-motion.
- `public/assets/` — фотографии артистов и локальный городской слой Санкт‑Петербурга.
- `dist/` — production-сборка после `pnpm run build`.
